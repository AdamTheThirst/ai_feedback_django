# enciclopedia.md

## Назначение раздела

Раздел «Энциклопедия» — это отдельный пользовательский раздел внутри веб-приложения, доступный только авторизованным пользователям.

Задача раздела:
- показывать список статей энциклопедии;
- давать пользователю открыть и прочитать отдельную статью;
- позволять администраторам и суперадминистраторам управлять статьями.

---

## 1. Общие правила

1. Энциклопедия доступна только авторизованным пользователям.
2. Все статьи заводятся и редактируются через административную часть.
3. И суперадмин, и админ могут:
   - создавать любые статьи;
   - редактировать любые статьи;
   - удалять любые статьи.
4. Для статьи используется отдельная таблица.
5. Пользовательский интерфейс энциклопедии в V1 — простой:
   - список статей;
   - пагинация;
   - отдельная страница статьи.
6. Сортировка статей в списке:
   - сначала заголовки, начинающиеся с цифр;
   - затем заголовки на русском алфавите от А до Я;
   - затем заголовки на латинице от A до Z.

---

## 2. Сущность статьи энциклопедии

### 2.1. Основные поля

У статьи должны быть следующие поля:

1. `title`
   - заголовок статьи;
   - обязательное поле;
   - максимум 128 символов с пробелами;
   - любые HTML-теги и иные теги в заголовке запрещены.

2. `body`
   - основной текст статьи;
   - обязательное поле;
   - максимум 5000 символов с пробелами;
   - в админ-интерфейсе рядом с полем должна быть предупреждающая пометка о лимите.

3. `summary`
   - краткое сутевое описание статьи;
   - генерируется через LLM;
   - отвечает на вопрос: «О чём эта статья?»;
   - длина: от 50 до 255 символов с пробелами;
   - стиль: деловой, без воды.

4. `is_published`
   - чекбокс `Опубликовано`;
   - если не установлен, статья не показывается пользователям в списке энциклопедии.

5. `slug`
   - уникальный человекочитаемый идентификатор для URL;
   - генерируется автоматически при создании статьи;
   - используется в ссылке на статью.

6. `created_by`
   - пользователь, который создал статью.

7. `updated_by`
   - пользователь, который последним редактировал статью.

8. `created_at`
   - дата и время создания.

9. `updated_at`
   - дата и время последнего обновления.

### 2.2. Rich text

Для поля `body` используется минимальный rich text.

Разрешено:
- обычный текст;
- абзацы;
- ссылки.

Не требуется в V1:
- изображения внутри статьи;
- загрузка файлов;
- сложная вёрстка;
- произвольный HTML.

### 2.3. Категории

Категории в будущем должны быть предусмотрены архитектурно.

Для V1:
- пользовательский интерфейс энциклопедии работает без категорий;
- структура проекта должна позволять позже добавить отдельную сущность категорий и связь статьи с категориями без перелома раздела.

---

## 3. Решение по URL статьи

Для статьи используется `slug`.

### Почему выбран slug

Это правильнее, чем использовать только ID, потому что:
- URL становится читаемым;
- ссылка на статью выглядит аккуратнее;
- это удобнее для будущего расширения проекта.

### Правила для slug

1. `slug` должен быть уникальным.
2. `slug` генерируется автоматически при создании статьи из заголовка.
3. При генерации нужно:
   - очистить строку от запрещённых символов;
   - привести её к безопасному формату URL;
   - при необходимости сделать транслитерацию.
4. Если такой `slug` уже существует, к нему добавляется уникальный суффикс.
5. После создания статьи `slug` не должен автоматически меняться при каждом изменении заголовка, чтобы не ломать ссылки.

## 4. Генерация краткого описания через LLM

### 4.1. Назначение

У каждой статьи должно быть краткое описание `summary`, которое отвечает на вопрос:
- «О чём эта статья?»

Это описание создаётся автоматически с помощью LLM.

### 4.2. Требования к summary

1. Только русский язык.
2. Деловой стиль.
3. Без воды.
4. Без markdown.
5. Без HTML.
6. Без списков.
7. Длина от 50 до 255 символов с пробелами.
8. Текст должен кратко и точно объяснять содержание статьи.

### 4.3. Источник для генерации

LLM получает на вход:
- заголовок статьи;
- текст статьи.

### 4.4. Мастер-промт для генерации summary

```text
Ты — редактор деловой базы знаний.

Твоя задача: по заголовку и тексту статьи подготовить краткое описание статьи, которое отвечает на вопрос «О чём эта статья?».

Требования:
1. Верни только готовый текст описания, без комментариев и без JSON.
2. Язык: русский.
3. Стиль: деловой, точный, без воды.
4. Длина: от 50 до 255 символов с пробелами.
5. Не используй markdown, HTML, эмодзи, кавычки-ёлочки вокруг всего текста и служебные пояснения.
6. Не начинай с фраз вроде «Статья о том, что...», если можно сказать точнее и короче.
7. Описание должно быть понятно человеку, который ещё не читал статью.
8. Не выдумывай факты, которых нет в заголовке и тексте статьи.

На вход подаются:
- Заголовок статьи
- Текст статьи

Сгенерируй одно краткое сутевое описание.
```

### 4.5. Поведение генерации

В V1 краткое описание должно жить в отдельном поле статьи и сохраняться в базе.

При создании или редактировании статьи система должна иметь возможность сгенерировать или перегенерировать это описание на основе актуального текста статьи.

---

## 5. Пользовательский интерфейс: список статей

### 5.1. Общая логика страницы

Когда пользователь открывает энциклопедию, он видит:
- фиксированный верхний заголовок `Энциклопедия`;
- список опубликованных статей;
- у каждой статьи заголовок и кнопку `Читать`;
- фиксированную нижнюю навигационную зону;
- сам список прокручивается между верхней и нижней фиксированными зонами.

### 5.2. Что отображается в списке

Для каждой статьи в списке показывается:
1. заголовок статьи;
2. кнопка `Читать` справа.

В V1 в списке не требуется показывать:
- summary;
- дату публикации;
- автора;
- счётчик просмотров.

### 5.3. Пагинация

Список статей должен быть с пагинацией:
- по 10 статей на страницу.

### 5.4. Какие статьи видит пользователь

Пользователь видит только статьи, у которых:
- `is_published = true`

### 5.5. Навигация на странице списка

#### Верхняя зона

Сверху страницы фиксируется заголовок:
- `Энциклопедия`

#### Нижняя зона

Снизу страницы фиксируется кнопка:
- `Назад к упражнениям`

Главный принцип:
- верхний заголовок всегда виден;
- нижняя кнопка всегда видна;
- список статей прокручивается под ними.

---

## 6. Пользовательский интерфейс: страница статьи

### 6.1. Общая логика страницы

Статья открывается на отдельной странице.

Пользователь видит:
- заголовок статьи;
- текст статьи;
- внизу фиксированную навигационную зону с двумя кнопками.

### 6.2. Нижняя навигация статьи

Внизу страницы статьи всегда видны две кнопки:
1. `Назад в энциклопедию`
2. `Назад к упражнениям`

Обе кнопки фиксированы внизу окна и не исчезают при прокрутке текста статьи.

### 6.3. Прокрутка статьи

Текст статьи прокручивается между:
- верхней частью страницы;
- нижней фиксированной навигационной зоной.

---

## 7. Правила публикации

1. Статья создаётся в таблице энциклопедии.
2. Статья может быть не опубликована.
3. Пока чекбокс `Опубликовано` не установлен, статья не видна пользователям.
4. После установки `Опубликовано` статья попадает в пользовательский список энциклопедии.

---

## 8. Правила редактирования и удаления

### 8.1. Кто может управлять статьями

И админ, и суперадмин могут без ограничений:
- создавать статьи;
- редактировать статьи;
- удалять статьи.

### 8.2. Логирование изменений

Для статьи обязательно хранить:
- кто создал;
- кто последний редактировал;
- когда создал;
- когда последний раз редактировал.

---

## 9. Ограничения по данным

### 9.1. Заголовок

- максимум 128 символов с пробелами;
- теги запрещены;
- должен храниться как чистый текст.

### 9.2. Текст статьи

- максимум 5000 символов с пробелами;
- в админке должна быть предупреждающая пометка о лимите;
- поле должно проверяться на серверной стороне.

### 9.3. Summary

- минимум 50 символов;
- максимум 255 символов;
- только текст;
- без тегов;
- без пустых или бессодержательных формулировок.

---

## 10. Таблица энциклопедии

Вся основная сущность статьи живёт в отдельной таблице.

Рекомендуемое логическое имя таблицы/модели:
- `EncyclopediaArticle`

Минимальный состав полей:
- `id`
- `title`
- `slug`
- `body`
- `summary`
- `is_published`
- `created_by`
- `updated_by`
- `created_at`
- `updated_at`

---

## 11. Что не требуется в V1

В V1 не требуется:
- открытый доступ без авторизации;
- изображения внутри статьи;
- прикреплённые файлы;
- счётчик просмотров;
- лайки, избранное, комментарии;
- сложная фильтрация;
- поиск по статьям;
- категории в пользовательском интерфейсе.

---

## 12. Краткая формулировка для Codex

Нужно реализовать раздел энциклопедии с отдельной таблицей статей.

У статьи есть:
- заголовок до 128 символов без тегов;
- текст статьи до 5000 символов;
- краткое описание `summary`, автоматически генерируемое через LLM;
- чекбокс `Опубликовано`;
- `slug` для URL;
- служебные поля автора и дат.

Пользователь видит только опубликованные статьи.

Страница списка:
- фиксированный верхний заголовок `Энциклопедия`;
- список статей по 10 на страницу;
- сортировка: цифры → русский алфавит → латиница;
- у каждой статьи справа кнопка `Читать`;
- снизу фиксированная кнопка `Назад к упражнениям`.

Страница статьи:
- отдельная страница;
- заголовок + текст статьи;
- снизу всегда видны две кнопки:
  - `Назад в энциклопедию`
  - `Назад к упражнениям`

Админ и суперадмин могут создавать, редактировать и удалять любые статьи.
