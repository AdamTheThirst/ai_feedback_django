# personal_cabinet.md

## Назначение раздела

Личный кабинет пользователя — это закрытый раздел веб-приложения, доступный только авторизованному пользователю.

Задачи раздела:
- дать пользователю доступ к своей базовой учётной информации;
- позволить сменить nickname;
- позволить сменить пароль через подтверждение по e-mail;
- показать историю завершённых игровых сессий с анализом;
- показать агрегированную персональную статистику;
- показать сильные и западающие аналитические индикаторы;
- дать доступ к просмотру анализа каждой игры и к скачиванию PDF.

---

## 1. Общие правила доступа

1. Личный кабинет доступен только авторизованному пользователю.
2. Пользователь видит только свои данные.
3. Через пользовательский интерфейс нельзя открыть чужой личный кабинет.
4. Внутри личного кабинета должен быть путь возврата к главной странице упражнений.
5. Общая кнопка `Выйти` остаётся глобальной кнопкой приложения и не дублируется отдельной кнопкой внутри кабинета.

---

## 2. Учётные данные пользователя

### 2.1. Что пользователь может менять

Пользователь может:
- менять свой nickname;
- менять пароль через подтверждение по e-mail.

Пользователь не может:
- менять e-mail.

### 2.2. Что нужно явно сообщить пользователю

На форме первичной регистрации должно быть явно указано:
- e-mail используется для входа, связи и восстановления пароля;
- e-mail после регистрации изменить нельзя.

### 2.3. Отображение в личном кабинете

В личном кабинете должны быть показаны:
- nickname;
- e-mail (только для просмотра);
- кнопка смены пароля / восстановления пароля;
- возможность редактирования nickname.

### 2.4. Смена nickname

1. Пользователь меняет nickname в личном кабинете.
2. Изменение сохраняется в учётной записи пользователя.
3. Для простоты реализации и поддержки проекта новое значение nickname считается текущим отображаемым именем пользователя во всех пользовательских разделах, где имя берётся из профиля.

Это решение выбрано как наиболее простое для реализации.

### 2.5. Смена пароля

Смена пароля должна использовать стандартный flow с подтверждением по e-mail.

В личном кабинете должна быть кнопка/ссылка, ведущая пользователя в сценарий смены/восстановления пароля.

---

## 3. Структура личного кабинета

Личный кабинет в V1 должен содержать следующие основные блоки:

1. **Профиль пользователя**
   - nickname;
   - e-mail;
   - редактирование nickname;
   - кнопка смены пароля.

2. **Мои показатели**
   - агрегированная статистика пользователя в карточках.

3. **Сильные стороны**
   - аналитические индикаторы, по которым пользователь показывает хорошие результаты.

4. **Зоны роста / западающие индикаторы**
   - аналитические критерии, где встречаются низкие оценки.

5. **История игр**
   - список завершённых сессий с анализом;
   - ссылка на просмотр анализа;
   - ссылка на скачивание PDF.

6. **Мои настройки игры**
   - персональная длительность игровой сессии от 5 до 20 минут.

7. **Навигация**
   - кнопка `Вернуться к упражнениям`.

---

## 4. Блок профиля пользователя

### 4.1. Поля

В блоке профиля показываются:
- `nickname` — редактируемый;
- `email` — только для чтения.

### 4.2. Ограничения

- e-mail не редактируется;
- пароль напрямую в кабинете не редактируется текстовым полем, а меняется только через защищённый e-mail flow.

### 4.3. Действия

Пользователь может выполнить следующие действия:
- сохранить новый nickname;
- перейти к смене/восстановлению пароля.

---

## 5. Блок «Мои показатели»

Этот блок должен быть оформлен карточками.

### 5.1. Состав карточек

В V1 нужно показывать следующие показатели:

1. **Всего сессий**
   - общее количество игровых сессий пользователя.

2. **Всего завершённых сессий**
   - количество сессий, завершённых с анализом.

3. **Общее количество прерванных попыток**
   - количество незавершённых игровых сессий.

4. **Средний балл по всем завершённым сессиям**
   - рассчитывается на основе суммарного результата каждой завершённой сессии;
   - используется только для сессий, в которых анализ был выполнен.

5. **Лучший результат**
   - лучший суммарный результат пользователя среди завершённых сессий с анализом.

6. **Средний балл по каждой игре**
   - отдельная карточка или группа карточек по каждой игре;
   - рассчитывается как среднее значение суммарных результатов завершённых сессий данной игры.

### 5.2. Источник данных

Все показатели подтягиваются из уже существующих таблиц:
- игровых сессий;
- результатов аналитики;
- игр;
- сценариев;
- статусов диалога.

### 5.3. Правила расчёта

1. В агрегированную статистику по результатам входят только завершённые сессии, по которым анализ был выполнен.
2. Прерванные попытки считаются отдельно.
3. Если у пользователя пока нет завершённых сессий с анализом, карточки со средними и лучшими значениями должны показывать корректное пустое состояние.

---

## 6. Сильные и западающие индикаторы

Под индикаторами понимаются аналитические критерии / аналитические промты, по которым система сохраняет текст анализа и числовую оценку.

### 6.1. Западающие индикаторы

Правило:
- любая оценка аналитического результата ниже `3` считается западающим индикатором.

В личном кабинете нужно показывать блок западающих индикаторов.

Для каждого такого индикатора рекомендуется выводить:
- название критерия;
- среднюю оценку по этому критерию;
- количество случаев, когда оценка была ниже 3.

Список должен быть отсортирован от самых проблемных к менее проблемным.

### 6.2. Сильные индикаторы

В личном кабинете нужно показывать и сильные стороны пользователя.

Для V1 сильным индикатором считается критерий, по которому:
- средняя оценка пользователя высокая;
- у пользователя нет систематически низких результатов по этому критерию.

Практическое правило для V1:
- сильными считать критерии с устойчиво хорошими значениями, ориентируясь на среднюю оценку по критерию;
- список показывать в порядке от самых сильных к менее сильным.

Для каждого сильного индикатора рекомендуется выводить:
- название критерия;
- среднюю оценку;
- количество анализов, в которых этот критерий оценивался.

### 6.3. Источник данных

Блоки сильных и слабых индикаторов должны строиться по таблице результатов аналитики пользователя.

---

## 7. История игр

### 7.1. Какие записи показывать

В истории игр показываются только:
- завершённые сессии;
- сессии, по которым выполнен анализ.

Отдельно в агрегированной статистике показывается:
- общее количество прерванных попыток.

### 7.2. Что показывать по каждой записи

Для каждой игровой сессии в списке должны отображаться:
- дата и время;
- название игры;
- название сценария;
- суммарный балл в формате `N из M`;
- статус;
- кнопка `Открыть результат`;
- кнопка/ссылка на PDF.

### 7.3. Пагинация

История игр должна быть с пагинацией:
- по 10 записей на страницу.

### 7.4. Фильтры

В V1 фильтры не требуются.

---

## 8. Просмотр анализа и PDF из личного кабинета

### 8.1. Просмотр анализа

Пользователь должен иметь возможность открыть полный анализ каждой завершённой игровой сессии прямо из личного кабинета.

### 8.2. PDF

Для каждой завершённой игровой сессии пользователь должен иметь возможность скачать PDF-версию результата.

Это обязательное требование.

---

## 9. Статусы в истории

Для истории и карточек достаточно следующих состояний:
- завершено;
- не завершено / прервано;
- время истекло;
- анализ выполнен;
- анализ не выполнялся.

На пользовательской странице истории должны отображаться только те записи, которые подходят под правила показа завершённых сессий с анализом.

Прерванные попытки участвуют в отдельном счётчике, но не обязаны выводиться в основном списке истории результатов.

---

## 10. Настройки игры пользователя

В личном кабинете должен быть отдельный блок пользовательских игровых настроек.

В V1 в этом блоке настраивается:
- персональная длительность игры от 5 до 20 минут.

### 10.1. Формат настройки

Рекомендуемый UI:
- ползунок или другой простой контрол выбора значения в диапазоне 5–20 минут.

### 10.2. Правило действия

Это персональная настройка конкретного пользователя.

Она влияет только на его собственные будущие игровые сессии и не меняет глобальное значение таймера для всех остальных пользователей.

---

## 11. Что не требуется в V1

В V1 не требуется:
- смена e-mail;
- удаление аккаунта пользователем;
- фильтры по истории;
- графики;
- доступ к чужим данным;
- логирование смены nickname в отдельной техтаблице.

---

## 12. Источники данных

### 12.1. Профиль

Источник:
- таблица пользователей / профиль пользователя.

### 12.2. История игр

Источники:
- таблица игровых сессий;
- таблица сценариев;
- таблица игр;
- таблица результатов анализа.

### 12.3. Агрегированная статистика

Источники:
- игровые сессии пользователя;
- результаты анализа пользователя.

### 12.4. Сильные и слабые индикаторы

Источник:
- числовые оценки по аналитическим промтам для завершённых сессий пользователя.

---

## 13. Краткая формулировка для Codex

Нужно реализовать личный кабинет только для авторизованного пользователя.

В кабинете должны быть:
- профиль пользователя;
- редактирование nickname;
- e-mail только для чтения;
- кнопка смены/восстановления пароля через e-mail flow;
- карточки со статистикой;
- блок сильных индикаторов;
- блок западающих индикаторов;
- история завершённых игр с анализом;
- доступ к просмотру анализа;
- доступ к PDF каждой игры;
- блок пользовательской настройки длительности игры 5–20 минут;
- кнопка `Вернуться к упражнениям`.

Правила статистики:
- отдельный счётчик всех сессий;
- отдельный счётчик завершённых сессий;
- отдельный счётчик прерванных попыток;
- средний балл по всем завершённым сессиям;
- лучший результат;
- средний балл по каждой игре.

Правило слабых индикаторов:
- любая оценка ниже 3 считается западающим индикатором.

Пользователь не может менять e-mail и не может удалить аккаунт.
